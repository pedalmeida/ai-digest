02
Story thread · new
Nick Cammarata claims agents disprove polysemanticity, enabling practical alignment

Polysemanticity has been the core unsolved problem in interpretability: neural networks appear to use individual neurons for many unrelated tasks, making it nearly impossible to trace why a model made a specific decision. This has blocked alignment research for years because you cannot reliably steer what you cannot understand. Cammarata's 26,000-word post argues that agents solve this by doing reasoning in latent space (internally), then externalizing only the necessary text outputs. The claim has sparked wild speculation but also cautious engagement from the research community.

What changed

Cammarata published a major thesis claiming agents inherently bypass polysemanticity by operating in latent space. Initial reactions range from 'this is groundbreaking' to 'needs peer review', but the post is generating serious engagement from Anthropic, Goodfire investors, and frontier labs.

Key signals
  • ◆Polysemanticity theory: neurons fire for multiple unrelated concepts simultaneously, making interpretation hard
  • ◆Cammarata's claim: agents that do internal reasoning in latent space can work around polysemanticity without relying on external text
  • ◆Practical implication: alignment becomes an engineering problem, not a fundamental blocker
What this means for you

If true, this flips the alignment constraint on agent design for your PT SMB workflows: you'd design agents to reason internally and expose only verified decisions, reducing hallucination risk in critical client tasks like invoicing or compliance.

New Claude Projects enables multi-agent workflows with internal message passing

Group chat for multi-agent orchestration has been a UX dead end: every agent sees every message, creating information overload and social dynamics (dominance, silence). Claude Projects moves to a message-passing architecture where agents work in separate threads and a coordinator agent manages state and decisions.

What changed

Claude Projects launched with a new architecture. Mollick tested it and confirms it's a genuine upgrade over the old Projects feature and over group-chat designs.

Key signals
  • ◆Architecture: user-facing coordinator + independent agents passing messages, not a group chat
  • ◆Advantage over group chat: avoids chaos, visibility issues, social friction in multi-agent tasks
  • ◆State: requires fiddling but is genuinely powerful for long-running projects
What this means for you

Test this for your agency: use Claude Projects to run a multi-threaded workflow for a single client—one agent handles payroll rules, another handles tax compliance, a third coordinates output. Eliminates the 'all agents talking at once' problem that kills context in group-chat agent systems.
