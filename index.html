Story thread · monitoring
Benchmarking industry has fundamental blindspots; metrics don't measure what ships
What changed

Systemic critique of benchmarking; not new, but now explicitly framed as an industry-wide problem.

Key signals
  • ◆Standard benchmarks (MMLU, GSM8K) measure reasoning in isolation; they don't measure agentic performance, planning depth, tool use, or recovery from errors
  • ◆No consensus metric for agent reliability, hallucination severity in production, or task completion under real constraints
  • ◆Benchmarking industry conflates 'difficult' with 'useful'; easy tasks that ship are worth more than hard tasks that don't
What this means for you

Don't trust model leaderboards when evaluating tools for your agency. Always test agents on your actual workflows, not on public benchmarks. A model that ranks #1 on MMLU might fail silently at multi-step document review or lead qualification. Build your own evals based on real client tasks.

Recommended action

watch|File this as a reason to build custom eval frameworks for each client use case, not rely on model rankings.

Why this made the cut: Saves you from picking wrong models; affects build decisions.

Legora agents operate on client data with zero visibility; how do you build and test without seeing traces?

07
Story thread · new
Building legal agents when you can't see a single trace of what they do

Legora is one of the fastest-growing legal tech startups; started in a Stockholm basement with ChatGPT and Swedish law. Today, lawyers use it to draft Word documents, review 10,000 contracts in a spreadsheet, and run due diligence. Agents coordinate work between lawyers, clients, and other agents.

What changed

First public deep-dive into how a production legal agent handles privacy constraints; gives you a working blueprint.

Key signals
  • ◆Client data is privileged; Legora cannot access even a single trace of what its agents do inside law firm databases
  • ◆Solution: build test environments modeled on customer workflows (inspired by RL 'worlds'), run full evaluations offline, then push agents to production
  • ◆Citation accuracy jumped from 70% to 99% after one release—no data insight required; quality improvements came from better prompting and model selection, not from trace-driven debugging
What this means for you

This is a direct pattern for your SMB agency. If you're handling sensitive client data (payroll, HR, legal documents), you cannot rely on production traces for debugging. Build offline test suites that mirror client workflows, use synthetic data, and run evaluations before deployment. Legora's approach—build worlds, not debugging panels—is the template.

Recommended action

investigate|If you're building agents for confidential client workflows, adopt Legora's 'worlds-based testing' approach. Build offline test suites before deployment.

Why this made the cut: Direct operational pattern for your agency; privacy-first agent design.
