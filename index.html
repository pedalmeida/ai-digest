PHP powers ~76% of the web. Two critical RCEs in core PHP (affecting the entire 8.x line) were discovered by AI agents during security research. What changed

Exploits now live in the wild. Vercel and major platforms deployed emergency mitigations. PHP Foundation issued emergency updates. This is no longer a researcher-only story—it's operational risk for any platform running PHP.

Key signals
  • ◆$40,000 of compute used by OpenAI's Patch the Planet initiative to discover critical Chrome vulnerability affecting ~1 billion users
  • ◆Coordinated disclosure failed: PHP2Shell exploits circulated live within 72 hours despite two-month mitigation effort with PHP Foundation
  • ◆OpenAI and PHP Foundation co-led coalition response; Vercel proactively deployed firewall-level mitigations before official patch
What this means for you

If you're building or selling AI services to Portuguese SMBs relying on PHP-based infrastructure (most legacy web stacks), this signals a new threat model: agents can now find and weaponize zero-days faster than disclosure timelines. Patch urgency is now measured in hours, not weeks.

Recommended action

Why this made the cut: First real-world proof that agent-speed vulnerability discovery breaks coordinated disclosure. Operational security threat for your clients.

Karpathy: LLM output interpretation becomes the new bottleneck, not capability

Karpathy observed that the AI community is moving past 'does the model know this?' to 'can we understand what it's saying?' This is a maturity signal: outputs are increasingly correct but still opaque. The bottleneck has moved downstream.

What changed

Karpathy published concrete techniques (ASD-STE100, voice input patterns) that improve output clarity. These are immediately actionable.

Key signals
  • ◆ASD-STE100 controlled language produces clearer, more parseable model outputs; models respond to explicit language constraints
  • ◆Voice rambling sessions reduce typing friction; LLMs perform better with more unstructured context input
  • ◆Testing paradigm shift: less time on benchmarking capability, more time on understanding what models *actually output* in production
What this means for you

When you're building agency workflows for SMBs, the edge is now in output parsing and interpretation, not prompt engineering. Karpathy's techniques—especially controlled language for structured outputs—directly improve agent reliability. Test ASD-STE100 prompting for any task requiring parseable outputs (code, JSON, structured reports).

Recommended action

Why this made the cut: Signals a fundamental shift in where engineering effort now matters most; directly applicable to agency work.
