Story thread · new
Karpathy techniques for extracting and understanding LLM reasoning

Karpathy is articulating patterns that work in practice, not theory. These are debugging and prompt-design techniques that improve reliability and interpretability of model outputs.

What changed

High-engagement posts from a respected builder; no major technical release, but practical signal that understanding LLM outputs is now a core skill.

Key signals
  • ◆ASD-STE100 controlled language (aviation standard) makes LLM explanations more precise and debuggable than free-form text
  • ◆Long ramble sessions: when user intent is fuzzy, let LLM hear 10+ minutes of unstructured voice input; more bits reduce interpretation error
  • ◆Large token budgets ($10 for 1M tokens with Opus 5): spend compute on understanding, not just generation; test with complex tasks like adapting Lord of the Rings
What this means for you

Immediately applicable to agency work: use controlled languages when you need precise LLM output for client deliverables (e.g., financial reports), and test ramble-based onboarding for complex projects. The controlled-language approach could reduce hallucinations in your SMB automation workflows.

Recommended action

test, use ASD-STE100 or similar structured language in your next client deliverable requiring precise output
